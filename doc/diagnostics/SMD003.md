# SMD003: Message type is not accessible from generated code

| | |
| --- | --- |
| Severity | Warning |
| Category | Sharp.Mediator |

## Message

> Message type '{0}' (or its response type) is private, protected, or file-local, or nested in such a type, so generated code cannot reference it. Handler '{1}' is excluded from generated dispatch and registration; make the message, and any type it is nested in, internal or public.

## Cause

Generated dispatch and registration code lives outside the message's declaring type and cannot name a `private`, `protected`, or `file`-local message or response type, or one nested in such a type. A constructed type is only as accessible as its type arguments, so `List<Secret>` counts as private when `Secret` is, and so does `Box<Secret>.Message`, which is nested in `Box<Secret>`. `private protected` counts as `protected` here. The handler for that message is left out of generated dispatch and registration, so it is not wired up the way the others are. For an event, nothing else declares a handler for it either, so publishing it reaches none of its handlers, including one registered in the service collection directly, and throws nothing: an event without a declared handler publishes to none.

## How to fix

Make the message type and its response type, and any type either is nested in or takes as a type argument, `internal` or `public`.

```csharp
// Flagged
file sealed record Ping : IRequest<int>;

// Fixed
internal sealed record Ping : IRequest<int>;
```

## Suppression

SMD003 is a warning. Suppress it only when the consequence above is what you want.

```csharp
#pragma warning disable SMD003
// ...
#pragma warning restore SMD003
```

```ini
# .editorconfig
dotnet_diagnostic.SMD003.severity = none
```
